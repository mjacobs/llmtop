# llmtop v0.1.0

The first tagged release of llmtop, the terminal UI that shows NVIDIA GPU
utilization side by side with what the llama.cpp, vLLM and NInfer servers on
those GPUs are actually doing. Everything in the public repository up to
`ad49c2b` is in it; the tag points at that commit.

Install from source with `make install`, or run `llmtop --demo` to see the UI
without any hardware.

## What you get

- Per-GPU utilization, memory, temperature and power as braille history
  charts, with GPU usage split between LLM serving and everything else.
- Per-server detail for llama.cpp and vLLM: model loaded, prompt and
  generation tokens per second, KV-cache use and slot occupancy. NInfer has no
  metrics endpoint, so it shows model, context length and concurrency limit.
- Local discovery by process scan, plus statically configured endpoints for
  servers the scan cannot see.
- Remote hosts in the same window through `llmtop agent`, an HTTP telemetry
  endpoint with an optional bearer token and a systemd user unit.
- A demo mode with synthetic data, and a layout that adapts from one GPU to
  several hosts.

## Fixed since the last published commit

Three fixes for the vLLM and NInfer support land in this release:

- A vLLM API key passed on the command line could be recorded and served as
  the model name, exposing it to anyone who could read the snapshot or history
  API. Only the positions vLLM itself resolves a model from are read now
  (`d9a7274`).
- Statically configured endpoints were always polled with the llama.cpp API,
  so a declared vLLM or NInfer server reported nothing useful. Endpoints now
  carry an optional `kind` key that selects the right adapter; existing
  configs keep working (`99a21a5`).
- The compact server row told every engine to restart with llama.cpp's
  `--metrics` flag. The hint now matches the engine that is running
  (`ad49c2b`).

(RTX 5090, RTX 4000 SFF Ada):

- `make check` — pass. gofmt, `go vet`, golangci-lint (0 issues), and the unit
  tests across all ten packages.
- `make test-nvml` — pass. `TestNVMLSmoke` read both GPUs live (utilization,
  memory, temperature, power) and enumerated 31 GPU processes;
  `TestNVMLGuardsBeforeInit` passed.
- `llmtop --demo` renders correctly at 200x50 with reserved demo names only.
- `make build VERSION=v0.1.0` stamps `llmtop v0.1.0`, so the tag becomes the
  version in `llmtop version`, the TUI's expanded help and the agent's
  advertised version.
- Privacy scan: gitleaks 8.30.1 over the working tree and over all 119 commits
  reachable from any ref found one match, the documentation placeholder
  `Bearer some-shared-secret` in `README.md` — not a credential. A term scan of
  the release tree, every blob in history and every commit message against
  private-term rules kept outside the repository plus generic private-network, private-domain and
  `/home/<user>` patterns found 0 matches. Every address and hostname in the
  tree is a reserved documentation name (`192.0.2.0/24`, loopback,
  `example.com`, `gpu-box`). Commit authorship is `mjacobs@apache.org` and
  dependabot only.
- Code review: each of the three commits was reviewed with no issues found.

## Publishing v0.1.0

Run from a checkout of this repository. Steps 1 and 2 are the only ones that change
the public repository before CI has seen the new commits.

```bash
set -euo pipefail

# 0. Confirm the starting point: three unpushed code commits plus these notes.
git fetch origin
git log --oneline origin/main..main
git log --oneline main..agent/mncx

# 1. Land these release notes on main, then publish.
git switch main
git merge --ff-only agent/mncx
git push origin main

# 2. Wait for the run on the pushed tip, not just the latest main run
#    (an older run can still be in flight when a race lands elsewhere).
sha="$(git rev-parse main)"
run_id=""
while [ -z "$run_id" ]; do
  run_id="$(gh run list --branch main --json databaseId,headSha \
    -q ".[] | select(.headSha==\"$sha\") | .databaseId" | head -1)"
  [ -z "$run_id" ] && sleep 5
done
gh run watch --exit-status "$run_id"

# 3. Tag the validated commit and push the tag.
git tag -s v0.1.0 ad49c2b -m "llmtop v0.1.0"
git push origin v0.1.0

# 4. Update the "Not verified" section above first: CI passed in step 2,
#    so drop the "GitHub CI has not run" clause before it ships as the
#    public release body. Then create the release from these notes.
gh release create v0.1.0 --verify-tag \
  --title "llmtop v0.1.0" \
  --notes-file docs/releases/v0.1.0.md

# 5. Verify the result.
git ls-remote --tags origin 'refs/tags/v0.1.0'
gh release view v0.1.0 --json tagName,isDraft,url

# 6. Install from a checkout or worktree at the tag, not this tree — this
#    tree is one commit ahead of v0.1.0, so `make install` here would stamp
#    a `-1-g<sha>` version instead of the tag.
release_tmp="$(mktemp -d)"
release_tree="$release_tmp/worktree"
git worktree add "$release_tree" v0.1.0
make -C "$release_tree" install
llmtop version   # expect: llmtop v0.1.0
git worktree remove "$release_tree"
rmdir "$release_tmp"
```

The tag deliberately points at `ad49c2b`, the exact tree that was validated
above, so the release-notes commit sits one commit ahead on `main`. Tagging the
notes commit instead is equally safe — it changes no code — if you would rather
have the notes inside the tag.

## Not verified

GitHub CI has not run on `d9a7274`, `99a21a5` or `ad49c2b` (local `make check`
only, on Go 1.27 rather than the 1.26 floor); no vLLM or NInfer server was
exercised live, so those adapters and the new engine-specific hints rest on
unit tests; the release ships source only, with no prebuilt binaries or
packaging; `README.md` still says CI pins golangci-lint v2.12 while CI and the
Makefile pin v2.13; no check here establishes that any earlier private
hosting copy of this repository was deleted. The privacy scan is bounded by its
pattern set (private-term rules, network/domain patterns, and absolute home
paths); plain reference numbers, relative paths, and bare service names still
need a human inspection before publication.
